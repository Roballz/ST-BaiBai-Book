# TXT / MD 额外知识库（试用）

入口：设置 → 向量记忆 → 额外知识库。开启向量记忆和知识库召回；Embedding 与 Query 重写沿用现有配置。

## 使用

1. 进入目标角色的聊天，设置分隔符（默认 `=========`）和文件编码，再选择 TXT/MD。
2. 预览独立区块，确认内容与编码正确；点击“确认导入并向量化”才向已配置的 Embedding 服务发送各块文本。导入过程可取消。
3. 设置知识库独立的召回块数、相似度阈值和字符预算；文件可分别停用、导出文本或删除。更改分隔符后需重新选择文件。

```text
设定：AA……
=========
设定：BB……
```

仅独占一行（允许两端空白）的分隔符生效；空块略过，行内同样字符保持原样。Markdown 按原文保存。每块独立向量化和召回，BB 命中不会自动附带 AA；AA 若独立达标，仍可能另外被召回。预算不足时跳过整块，不截断或自动补相邻块。

支持 UTF-8、GB18030/GBK、UTF-16 LE/BE；不支持 DOC/DOCX。单文件上限 5 MB、1000 块，每块上限 24000 字符，超限需手动分割。

## 存储与召回边界

- 当前角色隔离，同角色不同聊天共享；**文件目录、正文和向量均保存在当前浏览器 IndexedDB**，不写入聊天叶子，不自动同步柏宝库或其他设备。清理浏览器站点数据会删除知识库，请保留原始文件或导出文本。文本导出保留区块内容和分隔符，不包含向量。
- 即使柏宝库在线，知识库仍固定使用现有本地 VectorStore，防止自动切换后端造成文件与索引失配。摘要召回继续沿用原来的存储策略。
- 一次 Query LLM 改写与一组 query 向量供摘要、知识库共用。知识库按 embedding 相似度独立筛选，不另发 query 或 rerank，不占摘要/原文召回额度。只有知识库的新聊天也能召回。
- 结果在同一召回注入槽内排在摘要后面，以 `【额外信息】` 分隔。外部参考资料不标作已发生剧情。
- Embedding 地址或模型改变后旧文件停止召回，请导出后重新导入，确认成功再删旧文件。导入全部成功后才发布目录；失败/取消不发布，清理该次临时向量。进程意外关闭可能留未发布的孤立向量，但不会被召回。
- 缓存包含角色、知识库版本和召回参数；返回前复核聊天、配置和文件版本，切聊天、删除、停用或取消后的旧结果不注入。知识库不可读时摘要仍可继续。
