# 本地摘要 BM25 与混合召回

状态：`implemented_unverified`，待 Chat review 与 ST/TT、手机现场验证。
基线：`8f7983a`，分支 `codex/item-keywords-presence`。

## 使用与额度

入口：设置 → 向量记忆 → 召回参数。保留现有 Query、Embedding、Rerank 配置。

| 参数 | 含义 |
| --- | --- |
| 向量候选数 | 原 `rerankCandidates`，按多 Query 最高余弦召回，不先套 embedding 阈值 |
| BM25 候选数 | 当前聊天的摘要词法候选数；默认 0 关闭，启用可先设 20 |
| 融合后重排候选上限 | 两路去重、RRF 后最多送入 rerank 的候选数；默认 20，0 不重排 |
| 最大 BM25 摘要数 | 注入总数内最多给 BM25 摘要的名额；默认 2 |
| 最大原文数 | 沿用原文升级上限，两路候选均可竞争 |
| 注入总数 | 原文、BM25 摘要、向量摘要三者总上限 |

数量运行时规整为 0～200 的整数；旧配置缺融合上限时沿用旧向量候选数。BM25 关闭时走原生向量候选路线。

1. LLM 生成 INTENT 与多条 Q，Q 生成向量。保留原生 Query/Embedding 失败就结束本轮的行为。
2. BM25 用最新未排除的 User 正文与改写 Q 分别检索，按最高词法分合并，保留原始名称/编号。
3. 向量列表和 BM25 列表按 scope + leafId 去重，RRF 使用固定 `k=60`；两路各一张榜，向量多 Q 不重复投票。
4. 截取融合候选，以 INTENT 对对应楼层原文 rerank；原文清洗和缺原文时退摘要沿用原实现。
5. 先按 rerank 选原文；再遍历完整 BM25 候选榜，跳过已选 leafId、顺延补摘要；最后按 embedding 排名补达标向量摘要。
6. 三类共用 leafId 已选集合和注入总额。跨 scope 同 leafId 的最终去重沿用旧行为，但不同 scope 的内容和分数不混合。知识库独立额度不变。

例如 BM25 顺序 A/B/C/D，A 已升原文、BM25 摘要上限为 2，则摘要选 B/C。若 A/B 均升原文，则选 C/D。升原文不消耗 BM25 摘要名额。候选不足的空位由向量摘要补，不能突破 BM25 上限。

未进入 rerank 的 BM25 候选仍可补摘要。BM25 摘要不套 embedding 或 rerank 阈值，但只取实际有词法命中的正分结果；它不是“已经精排通过”的结果。

## 回退与数据边界

- Rerank 请求失败：保留原生向量行为，按余弦排序并把余弦作为回退分；因此仍可能达到原文阈值。BM25 独有候选没有余弦，只能按自身榜补摘要。调试页标识“向量回退”，失败结果不缓存。
- BM25 Worker 创建/执行失败：本轮继续向量召回，调试页显示失败。索引落盘失败则继续内存检索并显示降级。
- BM25 本身不请求任何模型服务；进入原文升级候选的内容仍会像原向量候选一样发给配置的 Rerank 服务。
- 仅索引当前聊天与向量索引同口径的有效叶子摘要：排除 omit、失效 swipe、种子叶子，搜索时排除当前全文窗口。继承 bundle、知识库及柏宝库后端不新增 BM25 接口。
- 现有摘要向量 IndexedDB 和原始聊天不迁移、不重写。新增 `bbs_bm25_local` 数据库，`indexes` 表按角色库名 + 聊天 scope 保存 MiniSearch 序列化索引、摘要与分词版本。
- MiniSearch 7.2.0 的 BM25+ 在内联 Worker 中运行。优先 `Intl.Segmenter` 中文分词；不支持的 WebView 回退汉字双字组。未复制 Anima 的词典触发/标签加权规则。
- 首次查询建索引，以后逐项核对当前有效摘要，只添加、删除或替换变化项；有变化才保存索引快照。Worker 仅缓存当前 scope。索引是派生缓存，可由聊天摘要重建，不是档案备份。
- 每次查询仍传输当前摘要列表到 Worker 并核对版本；不是无限规模、零全量遍历的索引协议。手机容量和延迟未测。
- 摘要/原文指纹、聊天、配置、近期窗口相关输入参与缓存及异步结果复核。取消只撤销等待，Worker 已开始的派生索引操作可能完成；其旧结果不得注入。
